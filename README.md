# Job Application Assistant

职聘通·网申助手：由 DeepSeek 结合已有 JSON 资料、自然语言补充文本和网页上下文，判断并补填网申表单。

当前版本 **3.0.0**，支持 Chrome / Edge 110 及以上版本。

- 一个 **一键填写本页** 按钮，全部字段交给模型判断。
- 保留 **完整编辑** 的结构化资料、JSON 保存、导入和导出。
- **新增 / 补充用户信息** 支持直接描述信息或粘贴简历片段，无需写 JSON、无需逐条定义字段。
- 参考同一区域网页已填内容，默认保护已有输入，并提供右下角悬浮入口和固定窗口。

## 快速开始

### 1. 下载并安装

1. 点击本仓库 **Code → Download ZIP**，或[直接下载源码](https://github.com/BistuDu/Job-Application-Assistant/archive/refs/heads/main.zip)。
2. 解压后找到直接包含 `manifest.json` 的目录，通常名为 `Job-Application-Assistant-main`。
3. Chrome 地址栏打开 `chrome://extensions`；Edge 从 **扩展 → 管理扩展** 进入。
4. 开启 **开发者模式**，点击 **加载已解压的扩展程序 / Load unpacked**，选择上面的目录。
5. 在浏览器扩展菜单中找到 **职聘通·网申助手**，固定到工具栏并打开。

安装参考：[Chrome 官方说明](https://developer.chrome.com/docs/extensions/get-started/tutorial/hello-world#load-an-unpacked-extension)、[Edge 官方说明](https://learn.microsoft.com/en-us/microsoft-edge/extensions/getting-started/extension-sideloading#locally-installing-and-running-an-extension)。

从浏览器扩展入口打开主页；直接双击 `popup.html` 或用 `file://` 打开只能查看静态界面，无法执行保存、配置和填写。
扩展直接加载源码即可使用；Node.js 仅用于开发测试。

### 2. 保存主要资料，再按需补充文本

> [!IMPORTANT]
> **先使用「完整编辑」维护已有 JSON 主要资料。**
> 信息不足或缺少对应字段时，在 **「新增 / 补充用户信息」** 中直接输入文本描述。

1. 点击 **完整编辑**，填写姓名、教育背景、工作经历、家庭成员等主要资料，再点击 **保存**。
2. 已有 JSON 资料可在完整编辑器中 **导入JSON → 保存**；**导出JSON** 可用于备份。
3. 需要补充时回到主页，点击 **新增信息**。
4. 在 **补充资料（直接描述）** 中输入真实信息或粘贴简历片段，点击 **保存用户信息**。

补充文本可以这样组织（示意，请填写你自己的真实内容）：

```text
母亲的姓名是……，电话更新为……，工作单位是……。
我持有……类别的驾驶证。
第二段实习在……公司，岗位是……，时间为……，主要负责……。
```

说明清楚属于谁、哪段经历，以及日期等事实；模型会结合这些描述直接提取对应内容。
新增补充文本不覆盖已有 JSON 主要资料；再次从完整编辑保存、导出时，也会保留补充文本。
仅有文本资料时也可以执行填写，不要求先建立固定 JSON 字段。

旧版“信息名称 + 内容”资料会自动显示为可编辑文本。保存文本后以这份文本作为补充来源，
不再重复使用旧版补充内容；保存空文本可清除当前补充来源，不会复活旧值。
完整编辑中的 **载入示例** 仅供参考格式，请替换成真实资料再保存。示例身份证号与电话留空。

### 3. 配置 DeepSeek

1. 在 [DeepSeek 控制台](https://platform.deepseek.com/api_keys) 创建自己的 API Key，可参考[首次调用说明](https://api-docs.deepseek.com/)。
2. 在扩展主页展开 **DeepSeek 设置**，输入 Key，选择界面提供的模型（默认 **DeepSeek Flash**）。
3. 点击 **保存配置**，看到 **Key 已保存** 后即可发起填写；实际有效性会在请求时验证。

模型调用使用你的 DeepSeek 账户。Key 无效、余额不足、限流或超时会显示具体原因。
未配置 Key 时不会提前填写任何字段。

### 4. 打开网申页面并一键填写

1. 打开企业网申页面，进入要填写的页面并展开表单。
2. 点击工具栏扩展图标，或网页右下角 **⚡ 悬浮球**。
3. 点击 **一键填写本页**，等待 DeepSeek 判断与填写，查看 **已填、已保留、待处理** 数量。

程序每次读取当前网页可见原生控件，并把同一行、卡片或分区已有信息作为上下文。
例如网页已选 **关系＝母亲**，模型会据此判断空白姓名、电话应对应母亲；
姓名可能来自已有 JSON，而更新后的电话可能从补充文本中提取。
网页已有的实习单位等线索，也会帮助模型判断对应哪段经历。

默认开启 **保护已有信息（仅填空白项）**，你手动补完后再次点击也会保留已有内容。
**空缺项自动填「无」** 由模型结合用户许可判断，仅用于已有 JSON 中为空的经历、语言、证书等资料；
文本没提及某件事不等于“没有”。需要保持空白时可取消勾选。

### 5. 核对、补充和翻页

核对实际填写结果，手动处理验证码、简历上传、同意条款及不支持的自定义控件，再手动提交网申。
资料不足或冲突时，无法确认的字段应留待手动处理；必要时补充真实资料后重试。
误填内容可先清空再填，或在主页明确关闭保护后更正。
切换下一页、展开新字段或手动添加新的经历行后，再次点击填写，程序会重新扫描当前页面。

点击 **固定窗口**，或悬浮面板 **新增信息 / 打开固定主页**，可打开绑定来源网申标签页的独立窗口。
悬浮面板默认保护已有信息，滚动或点击网页不会自动关闭。

## 常见问题

| 现象 | 处理方式 |
| --- | --- |
| 找不到 `manifest.json` | 解压 ZIP，选择直接包含该文件的目录。 |
| 直接打开 `popup.html` 按钮无效 | 通过扩展管理页安装，从工具栏打开扩展。 |
| 没有悬浮球 | 开启 **网页右下角显示悬浮球**，刷新网页；浏览器内部页和 `file://` 等受限页面不显示。 |
| 提示先保存资料 | 在 **完整编辑** 保存 JSON 资料，或添加并保存补充文本。 |
| Key 无效、余额不足、超时 | 检查 DeepSeek 账户、配置和网络，再按需重试。 |
| 部分字段未填写 | 查看待处理字段，检查资料是否清楚、日期是否完整、页面是否展开；特殊控件手动处理。 |
| 提示文本内容缺少原文依据 | 本批模型返回内容不能从原文核验，已停止；检查补充文本写法后重试。 |
| 已有内容未更新 | 默认保护已填字段，清空错误项或在主页显式关闭保护后重填。 |
| 等待期间页面或关系变化 | 旧结果跳过或停止，确认当前页面和线索正确后重新点击。 |
| 更新后仍是旧界面 | 在扩展管理页重新加载扩展，再刷新网申页并重新打开主页。 |

## 模型判断与本地执行

字段与资料匹配、人物/经历归属、下拉/单选选项含义均由模型判断。
本地负责 DOM 提取、来源与证据校验、控件约束、日期格式转换及写入，不提供字段匹配表或选项别名表。
验证码、密码、上传、条款、只读/禁用控件保护和地区联动保护仍保留。

一次最多处理 300 个待填写字段，每批 20 项。请求固定发送到
`https://api.deepseek.com/chat/completions`，使用 JSON 输出并关闭思考模式。
接口参考：[DeepSeek API](https://api-docs.deepseek.com/)、[JSON 输出](https://api-docs.deepseek.com/guides/json_mode/)。

模型方案支持两种资料来源：

| 来源 | 模型返回 | 本地处理 |
| --- | --- | --- |
| 已有 JSON 资料 | `sourcePath`，例如 `family.1.name` | 验证来源存在，从本地资料读取真实值。 |
| 自然语言补充文本 | `value` + `evidenceQuote`，`sourcePath: null` | 原文引文必须存在于补充文本，提取值必须是其中的摘录；验证后写入。 |

选项必须返回网页真实 `optionId`；未知或重复字段、伪造来源、缺少原文依据、不存在的选项、
截断回复、空回答和非法 JSON 均停止本批填写。额外的脚本、选择器等属性不会执行。
日期可从真实来源取年份或起止时间，不补造缺失的月、日；控件值不符合约束时不写入。

原文校验能拦截没有依据的文本，不能证明人物归属、字段含义或选项语义一定正确；实际提交前需核对。
JSON 与补充文本冲突时，模型应仅在更新对象明确时采用补充文本，否则跳过。

## 保存与兼容

- 完整编辑继续保存 `chrome.storage.local.profile` 的 JSON 对象，导入/导出功能保留。
- 新增信息的用户输入是纯文本，内部保存在 `profile.supplementText`；用户不必编写 JSON。
- 原有字段、经历、家庭成员和旧 `extraInfo` 数据保留；新补充文本保存后，旧 `extraInfo` 不再作为重复补充来源。
- 完整编辑正常保存及导出会保留最新补充文本；不同窗口的保存由后台依次合并。导入 JSON、载入示例、清空等主动替换操作按该操作的资料生效。

## 数据与隐私

资料与用户自己的 API Key 保存在本机浏览器扩展存储中，不随项目源码自动打包。
使用模型时，JSON 资料、补充文本、网页字段、选项及相关页面已有内容会发送给 DeepSeek。
Key 只放在认证头，不写入模型提示、任务进度或服务端错误正文。
源码和测试使用示例数据及假 Key；测试不调用真实 DeepSeek。

`chrome.storage.local` 限制为可信扩展上下文访问。悬浮脚本不读取资料值或 Key，
只获取准备状态、当前页面任务统计、启动本页填写或打开主页，不能修改其他标签页或用户资料。

后台执行请求，进度保存到 `chrome.storage.session`，关闭弹窗可继续处理。
后台重启会标记中断，已填内容保留，不自动重试计费。
每批首响应最多等待 25 秒，正文最多 60 秒；API 失败或后续批次中断时保留已经完成的填写。

## 项目结构

| 文件 | 职责 |
| --- | --- |
| `manifest.json` | 扩展入口、权限及悬浮脚本注册。 |
| `popup.html/css/js` | 保存补充文本、配置 Key、单一填写入口及结果。 |
| `editor.html/css/js` | 原有结构化 JSON 资料编辑、导入和导出。 |
| `deepseek-client.js` | 模型提示、JSON 来源整理、文本提取证据校验及请求。 |
| `fill-controller.js` | 扫描 → 模型 → 分批应用 → 清理，统计部分结果。 |
| `fill-engine.js` | DOM 描述、已有内容保护及控件写入；保存节点快照。 |
| `background.js` | 后台任务、配置、补充文本保存及来源文档定位。 |
| `floating.js` | 右下角悬浮入口和固定面板。 |
| `profile.example.json` | 保留的 JSON 示例模板，联系方式留空。 |
| `tests/` | 文本证据、JSON 兼容、DOM 保护和真实界面流程回归。 |

## 开发与测试

```sh
git clone https://github.com/BistuDu/Job-Application-Assistant.git
cd Job-Application-Assistant
npm install
npm test
```

测试需要 Node.js、Playwright 和本机 Chrome；使用 Edge 时可执行 `TEST_BROWSER_CHANNEL=msedge npm test`。
浏览器测试使用独立临时浏览器，只加载本地页面；网络响应和浏览器扩展 API 使用模拟适配器。
测试实际执行后台、客户端、主页、JSON 编辑器及填写引擎，不验证真实账户额度或模型识别质量。

## 当前支持边界

每次点击扫描当前可见 DOM，不持续监听后续字段。
不遍历 iframe / Shadow DOM，不直接操作纯 div/span 自定义组件，不自动增加网站经历行。
网站未知的异步联动仍可能影响其他字段；无法确认的字段应留待手动处理。
