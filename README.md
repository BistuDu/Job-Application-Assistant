# Job Application Assistant

职聘通·网申助手：用一段文字描述你的真实资料，由 DeepSeek 结合网页上下文判断并补填网申表单；
没填上的字段会说明原因，并按失败原因自动修正一次。

当前版本 **3.1.0**，支持 Chrome / Edge 110 及以上版本。

- 资料只以 **一段文字** 保存，不需要写 JSON、不需要逐条定义字段。
- 一个 **一键填写本页** 按钮，全部字段交给模型判断。
- 模型给出的每项内容都必须能在你的资料原文中 **逐字核验**，不能编造。
- 未填上的字段会逐条列出原因；可机械修复的失败会自动带原因重问一次（有界修复轮）。
- 默认保护网页已有输入，并提供右下角悬浮入口和固定窗口。

## 快速开始

### 1. 下载并安装

1. 点击本仓库 **Code → Download ZIP**，或[直接下载源码](https://github.com/BistuDu/Job-Application-Assistant/archive/refs/heads/main.zip)。
2. 解压后找到直接包含 `manifest.json` 的目录，通常名为 `Job-Application-Assistant-main`。
3. Chrome 地址栏打开 `chrome://extensions`；Edge 从 **扩展 → 管理扩展** 进入。
4. 开启 **开发者模式**，点击 **加载已解压的扩展程序 / Load unpacked**，选择上面的目录。
5. 在浏览器扩展菜单中找到 **职聘通·网申助手**，固定到工具栏并打开。

安装参考：[Chrome 官方说明](https://developer.chrome.com/docs/extensions/get-started/tutorial/hello-world#load-an-unpacked-extension)、[Edge 官方说明](https://learn.microsoft.com/en-us/microsoft-edge/extensions/getting-started/extension-sideloading#locally-installing-and-running-an-extension)。

从浏览器扩展入口打开主页；直接双击 `popup.html` 或用 `file://` 打开只能查看静态界面，无法执行保存、配置和填写。
扩展直接加载源码即可使用；Node.js 仅用于开发测试。

### 2. 用文字写清你的资料

> [!IMPORTANT]
> 资料只有一份文本。点 **✏️ 编辑资料** 写清事实，随时可用 **➕ 快速补充** 追加内容。

1. 点击 **编辑资料**，按自然语言写清姓名、电话、教育背景、经历、家庭成员、求职意向等真实信息。
2. 写明 **归属**：谁的、哪一段经历；行与行之间用换行分开即可。
3. 确实没有的项写清「没有」，例如「没有获得过竞赛奖项」——只有写了没有，网页上才会填「无」。
4. 点击 **保存**。资料只保存在本机，填写时整段发送给模型。

可以这样组织（示意，请替换成你自己的真实内容）：

```text
姓名：张某某
手机号码：13800000000
现居住地：北京市海淀区

教育背景：
2022.9-2026.6 某某大学 计算机科学与技术 本科

实习经历：
2024.7-2024.9 某某科技有限公司 前端开发实习生，负责……

家庭成员：
母亲 李某某，电话 13900000000

其他：
没有获得过竞赛奖项
```

日期写成 `2023.9-2024.6` 即可，需要单一年份或起止日期的字段会从这里取，不会替你补造缺失的月、日。
升级到 3.1 时，旧版 JSON 画像会 **自动改写成文本**（原文本 + 旧键值资料 + JSON 内容），不会丢失已有内容；旧 JSON 存储随之删除。

### 3. 配置 DeepSeek

1. 在 [DeepSeek 控制台](https://platform.deepseek.com/api_keys) 创建自己的 API Key，可参考[首次调用说明](https://api-docs.deepseek.com/)。
2. 在扩展主页展开 **DeepSeek 设置**，输入 Key，选择界面提供的模型（默认 **DeepSeek Flash**）。
3. 点击 **保存配置**，看到 **Key 已保存** 后即可发起填写；实际有效性会在请求时验证。

模型调用使用你的 DeepSeek 账户。Key 无效、余额不足、限流或超时会显示具体原因。
未配置 Key 时不会提前填写任何字段。

### 4. 打开网申页面并一键填写

1. 打开企业网申页面，进入要填写的页面并展开表单。
2. 点击工具栏扩展图标，或网页右下角 **⚡ 悬浮球**。
3. 点击 **一键填写本页**，等待 DeepSeek 判断与填写。

填写分两轮：第一轮判断并写入全部空白字段；只对 **可机械修复** 的失败（选项不存在、内容与原文对不上、
超长、日期格式、输入框校验不通过）自动带失败原因重问 **一次**，其余情况不再重复请求。

程序每次读取当前网页可见原生控件，并把同一行、卡片或分区已有信息作为上下文。
例如网页已选 **关系＝母亲**，模型会据此判断空白姓名、电话应对应母亲。

默认开启 **保护已有信息（仅填空白项）**。**资料说明没有的项自动填「无」** 只在你的资料明确写了
「没有……」时生效，并在下拉框中选择网页真实存在的「无 / 暂无 / 不涉及」选项；资料没提到某件事
不等于「没有」。需要保持空白时可取消勾选。

### 5. 看结果、补资料、翻页

结果里会分别列出：

| 结果 | 含义 |
| --- | --- |
| 已填 / 其中填「无」 | 已按资料原文写入网页的字段数。 |
| 已保留已有信息 | 网页原本就有内容，未覆盖。 |
| 按失败原因自动修正 | 第二轮重问后填上的字段数。 |
| 待处理 + 逐条原因 | 未填上的字段与原因，例如「资料中没有找到对应内容」「没有匹配的选项」「输入上限 50 字，资料内容 82 字」。 |
| 需你补充 | 模型说明缺少的资料，例如「缺少紧急联系人电话」。 |
| 需手动处理 | 上传文件、验证码、条款勾选、复选框/只读控件、地区联动等按名称列出。 |

按提示在 **编辑资料** 里补上对应内容后再次点击填写即可。核对无误后手动提交网申；误填内容可先清空，
或在主页显式关闭保护后更正。切换下一页或展开新字段后，再次点击会重新扫描当前页面。

点击 **固定窗口**，或悬浮面板 **编辑资料 / 打开固定主页**，可打开绑定来源网申标签页的独立窗口。

## 常见问题

| 现象 | 处理方式 |
| --- | --- |
| 找不到 `manifest.json` | 解压 ZIP，选择直接包含该文件的目录。 |
| 直接打开 `popup.html` 按钮无效 | 通过扩展管理页安装，从工具栏打开扩展。 |
| 没有悬浮球 | 开启 **网页右下角显示悬浮球**，刷新网页；浏览器内部页和 `file://` 等受限页面不显示。 |
| 提示先保存资料 | 在 **编辑资料** 中写入并保存你的资料文本。 |
| Key 无效、余额不足、超时 | 检查 DeepSeek 账户、配置和网络，再按需重试；这类问题不会重复请求。 |
| 待处理字段里写「资料中没有找到对应内容」 | 资料里确实没有这条信息，按「需你补充」提示补写后再填写。 |
| 待处理字段里写「资料内容超过输入长度限制」 | 该栏有字数上限，请在资料中改写为更短但仍完整的表述。 |
| 待处理字段里写「填写后被页面还原」 | 该控件不接受自动填写，请手动输入。 |
| 待处理字段里写「页面内容已变化」 | 填写期间页面或输入被改动，确认页面后重新点击填写。 |
| 已有内容未更新 | 默认保护已填字段，清空错误项或在主页显式关闭保护后重填。 |
| 更新后仍是旧界面 | 在扩展管理页重新加载扩展，再刷新网申页并重新打开主页。 |

## 模型判断与本地执行

字段与资料的对应、人物/经历归属、下拉/单选选项含义均由模型判断。
本地负责 DOM 提取、原文证据校验、控件约束、日期格式转换及写入，不提供字段匹配表或选项别名表。
验证码、密码、上传、条款、只读/禁用控件保护和地区联动保护仍保留。

一次最多处理 300 个待填写字段，每批 20 项，最多两轮。请求固定发送到
`https://api.deepseek.com/chat/completions`，使用 JSON 输出并关闭思考模式。
接口参考：[DeepSeek API](https://api-docs.deepseek.com/)、[JSON 输出](https://api-docs.deepseek.com/guides/json_mode/)。

模型只能返回「内容 + 原文依据」：

| 模型返回 | 本地校验 |
| --- | --- |
| `value` + `evidenceQuote` | `evidenceQuote` 必须逐字出现在资料文本中，`value` 必须是该引文中的内容，否则拒绝该字段。 |
| `optionId` | 必须是该字段网页真实提供的选项，且同时有原文依据；不生成新选项。 |
| `value: null` + `note` | 视为资料不足，`note` 会显示为「需你补充」。 |
| `fillNone: true` | 需要开关开启、引文明确说明「没有」，且填写内容是 无/暂无/没有/不涉及 之一。 |

不合法的条目 **逐条拒绝**，不影响同批其他字段；只有鉴权、余额、限流、超时、网络等问题才终止整个任务。
第二轮只重问可修复失败字段，并把失败原因、字段约束（长度/最小最大值/格式/控件类型）、
真实选项和上一轮内容一并交给模型；仍无法确定时必须返回空值并说明缺什么。

日期可从真实原文取年份或起止时间，不补造缺失的月、日；写入时按顺序尝试原生 setter、
`setRangeText`、聚焦后插入三种手法，写入后延迟复检一次，被页面脚本还原的字段不会谎报成功。
本地不会为了获得校验信息而触发提交按钮。

原文校验能拦截没有依据的内容，不能证明人物归属、字段含义或选项语义一定正确；实际提交前需核对。

## 保存与兼容

- 用户资料以纯文本保存在 `chrome.storage.local.userText`，不再保存 JSON 画像。
- 旧版 `profile` JSON 在扩展启动时一次性改写为文本（补充文本 + 旧键值资料 + JSON 内容）后删除，内容不丢失。
- 编辑资料页只提供文本编辑、示例与清空；`Ctrl/Cmd + S` 可保存，未保存时关闭会提示。
- 主页与编辑资料页共用同一份文本，保存后其他窗口自动同步。

## 数据与隐私

资料与用户自己的 API Key 保存在本机浏览器扩展存储中，不随项目源码自动打包。
使用模型时，资料文本、网页字段、选项及相关页面已有内容会发送给 DeepSeek。
Key 只放在认证头，不写入模型提示、任务进度或服务端错误正文。
源码和测试使用示例数据及假 Key；测试不调用真实 DeepSeek。

`chrome.storage.local` 限制为可信扩展上下文访问。悬浮脚本不读取资料内容或 Key，
只获取准备状态（是否已保存、字数）、当前页面任务统计、启动本页填写或打开主页，
不能修改其他标签页或用户资料。

后台执行请求，进度保存到 `chrome.storage.session`，关闭弹窗可继续处理。
后台重启会标记中断，已填内容保留，不自动重试计费。
每批首响应最多等待 25 秒，正文最多 60 秒；API 失败或后续批次中断时保留已经完成的填写。

## 项目结构

| 文件 | 职责 |
| --- | --- |
| `manifest.json` | 扩展入口、权限及悬浮脚本注册。 |
| `popup.html/css/js` | 保存资料文本、配置 Key、单一填写入口、结果与失败原因展示。 |
| `editor.html/css/js` | 资料文本编辑器：示例、清空、字数统计与保存。 |
| `deepseek-client.js` | 提示词、原文证据校验、逐条拒绝与带反馈的修正轮请求。 |
| `fill-controller.js` | 扫描 → 模型 → 应用 → 有界修正轮 → 清理，汇总待处理原因与待办。 |
| `fill-engine.js` | DOM 描述、已有内容保护、带原因码的写入与延迟复检。 |
| `background.js` | 后台任务、配置、资料文本保存与旧 JSON 迁移。 |
| `floating.js` | 右下角悬浮入口和固定面板。 |
| `tests/` | 原文证据、逐条拒绝、修复轮、DOM 保护与真实界面流程回归。 |

## 开发与测试

```sh
git clone https://github.com/BistuDu/Job-Application-Assistant.git
cd Job-Application-Assistant
npm install
npm test
```

测试需要 Node.js、Playwright 和本机 Chrome；使用 Edge 时可执行 `TEST_BROWSER_CHANNEL=msedge npm test`。
浏览器测试使用独立临时浏览器，只加载本地页面；网络响应和浏览器扩展 API 使用模拟适配器。
测试实际执行后台、客户端、主页、资料编辑器、悬浮球及填写引擎，不验证真实账户额度或模型识别质量。

## 当前支持边界

每次点击扫描当前可见 DOM，不持续监听后续字段。
不遍历 iframe / Shadow DOM，不直接操作纯 div/span 自定义组件或富文本编辑器，不自动增加网站经历行。
只认键盘事件的受控组件、以内部状态提交的表单可能填不进去，此类字段会在结果中标记为「填写后被页面还原」或「该控件不接受自动填写」。
网站未知的异步联动仍可能影响其他字段；无法确认的字段应留待手动处理。
