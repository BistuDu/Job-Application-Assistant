# Job Application Assistant

职聘通·网申助手：使用你保存的真实资料，结合网申页面已有内容，自动补填空白项。
支持自定义资料、规则 + DeepSeek / 纯 DeepSeek 两种模式、已有信息保护及网页悬浮入口。

## 快速开始

使用 Chrome 或 Edge 110 及以上版本。首次使用按下面五步操作；扩展直接加载源码即可使用，Node.js 只用于开发测试。

### 1. 下载并安装扩展

1. 在本仓库点击 **Code → Download ZIP**，或直接[下载源码 ZIP](https://github.com/BistuDu/Job-Application-Assistant/archive/refs/heads/main.zip)。
2. 解压 ZIP，找到包含 `manifest.json` 的目录。GitHub 下载的目录通常名为 `Job-Application-Assistant-main`。
3. 打开浏览器的扩展管理页：Chrome 地址栏输入 `chrome://extensions`；Edge 可从 **扩展 → 管理扩展** 进入。
4. 开启 **开发者模式**，点击 **加载已解压的扩展程序 / Load unpacked**，选择上一步包含 `manifest.json` 的目录。
5. 在浏览器工具栏的扩展菜单里，找到 **职聘通·网申助手**，固定到工具栏以便随时打开。

安装方式可参考 [Chrome 官方说明](https://developer.chrome.com/docs/extensions/get-started/tutorial/hello-world#load-an-unpacked-extension) 和 [Edge 官方说明](https://learn.microsoft.com/en-us/microsoft-edge/extensions/getting-started/extension-sideloading#locally-installing-and-running-an-extension)。

从浏览器工具栏的扩展图标进入主页。`popup.html` 是扩展内部页面，直接双击文件或用 `file://` 地址打开无法执行扩展的保存、配置和填写功能。

### 2. 保存自己的填写资料

1. 点击扩展图标，再点击 **新增信息**。
2. 在 **新增 / 补充用户信息** 中，自定义填写 **信息名称** 和 **信息内容**。
3. 点击 **添加一条信息** 可增加多条资料；填完后点击 **保存用户信息**。

信息名称由你决定，例如“姓名”“邮箱”“驾驶证”“母亲姓名”“母亲电话”，内容填写对应的真实资料。
名称要说明清楚内容属于谁、哪段经历，便于区分本人、家庭成员或不同实习记录。
需要维护教育背景、实习经历、家庭成员等结构化资料时，点击 **完整编辑**，填写后点击 **保存**。
已有 JSON 资料也可在完整编辑器内 **导入JSON → 保存**；导出的 JSON 可用于备份和迁移。

**载入示例** 只用于参考字段格式。请将示例改为自己的真实资料再保存，示例身份证号及电话为空。

### 3. 配置 DeepSeek

1. 在 [DeepSeek 控制台](https://platform.deepseek.com/api_keys) 创建自己的 API Key，可参考 [DeepSeek 首次调用说明](https://api-docs.deepseek.com/)。
2. 返回扩展主页，展开 **DeepSeek 设置**。
3. 填入 API Key，选择界面提供的模型（默认 **DeepSeek Flash**），点击 **保存配置**。
4. 出现 **Key 已保存** 后即可发起填写；实际 Key 和接口是否可用会在请求时验证。

模型调用使用你的 DeepSeek 账户。Key 无效、余额不足、限流或网络超时时，填写结果区域会显示对应原因。

### 4. 打开网申页面并填写

1. 打开企业官网的投递 / 网申页面，进入需要填写的那一页，并展开需要补填的表单。
2. 点击浏览器工具栏的扩展图标，或网页右下角的 **⚡ 悬浮球**。
3. 根据需要点击一个填写按钮：

| 按钮 | 处理方式 |
| --- | --- |
| **一键填写本页（模式1:规则+模型）** | 无上下文的明确字段先用规则填写；有相邻已填线索、歧义或规则未处理的字段交给 DeepSeek 判断。 |
| **一键填写本页（模式2:模型）** | 将可填写字段全部交给 DeepSeek 判断，再从本地真实资料取值写入。 |

程序会参考同一行、卡片或分区已经填写的内容，无需输入额外提示词。
例如，你已在网页上选择 **关系＝母亲**，且保存了母亲的真实资料，程序会据此判断空白姓名、电话应使用母亲的信息。
已有实习单位等线索也会参与对应记录的判断；资料不足或线索冲突时，无法确认的字段会留待手动处理。

扩展主页的 **保护已有信息（仅填空白项）** 默认开启，再次点击只补剩余空白项。
**空缺项自动填「无」** 仅适用于允许填无的经历、语言、证书等字段；需要保留这些空白时可取消勾选。

### 5. 核对结果、补充和翻页

查看结果区域的 **已填、已保留、待处理** 数量，核对实际填写内容。
验证码、简历上传、同意条款及未支持的自定义控件由你手动处理，最后手动提交网申。

遗漏的真实资料可在扩展中补充并保存，再点击填写；你在网页上手动补全的内容默认会保留。
如果某个字段误填，先清空该字段再重填。切换到下一页或展开新的字段后，再次点击 **一键填写本页**，程序会重新读取当前页面。
网站要求新增多段经历时，先手动添加对应表单行，再执行填写。

点击扩展主页的 **固定窗口**，或悬浮面板的 **新增信息 / 打开固定主页**，可以打开绑定当前网申标签页的独立窗口，便于边查看网页边补充资料。

## 常见问题

| 现象 | 处理方法 |
| --- | --- |
| 安装时提示找不到 `manifest.json` | 先解压 ZIP，再选择直接包含 `manifest.json` 的那一层目录。 |
| 打开 `popup.html` 后按钮无效 | 通过扩展管理页安装，从浏览器工具栏的扩展图标打开。 |
| 网页没有悬浮球 | 确认 **网页右下角显示悬浮球** 已开启，并刷新网申页面；浏览器内部页面、`file://` 等受限页面不显示。 |
| 提示先保存资料 | 在 **新增信息** 或 **完整编辑** 中保存自己的真实资料后重试。 |
| 提示 API Key 无效 / 余额不足 | 在 DeepSeek 控制台检查 Key 或账户状态，再到扩展设置中更新配置。 |
| 部分字段没有填入 | 查看待处理字段，检查资料、日期格式、选项和当前页面是否展开；特殊控件可手动填写。 |
| 页面已有值没有被更新 | 默认保护已有内容；需要更正时先清空错误项再填，或在主页明确关闭保护。 |
| 等待期间页面或关系已变化 | 旧结果会跳过或停止；保持当前页面及线索正确后重新点击填写。 |
| 更新源码后仍显示旧界面 | 在扩展管理页重新加载扩展，再刷新网申页面并重新打开扩展主页。 |

## 数据与隐私

你保存的资料和 API Key 存放在本机浏览器扩展存储中。
使用模型时，画像资料、网页字段描述、选项文本及相关页面已填内容会发送给 DeepSeek；Key 只用于接口认证。
模式1在规则已处理全部字段时不会请求模型。项目源码不包含真实 Key，浏览器本地保存的资料也不会随源码 ZIP 自动打包。

## 实现概览

原生 HTML/CSS/JavaScript 编写的 Manifest V3 浏览器扩展，当前版本 2.11.1。
画像与用户自己的 DeepSeek API Key 保存在 `chrome.storage.local`。
点击填写后，由扩展后台请求 DeepSeek，再通过 `chrome.scripting.executeScript`
在目标文档执行 `FILL_FUNCTION`。需要 Chrome/Edge 110 或更新版本。

## 两种填写模式

- **一键填写本页（模式1:规则+模型）**：规则先填明确字段，然后 DeepSeek
  批量处理未识别、歧义、格式/选项未匹配和缺数据的可编辑字段。
  如果规则已经全部填完，不请求 DeepSeek；模型失败时保留已填内容。
- **一键填写本页（模式2:模型）**：只提取可填写字段，不使用规则决定画像映射；
  所有可填写字段交给 DeepSeek 判断，然后由本地引擎执行。

两种模式都保留验证码、文件上传、密码、只读控件和条款的保护检查。
这些检查决定能否操作控件，不替模型决定字段对应哪个画像内容。

首次使用，在扩展的 **DeepSeek 设置**中填入自己的 API Key、选择模型、点击保存配置。
留空 Key 再保存可以保留原 Key；“删除 Key”会移除已保存的配置。
保存只表示配置已存储，实际接口可用性会在填写时验证。
示例模板的身份证号、电话等联系方式留空，使用前请填写自己的真实资料。

## 根据网页已有信息推断

两种模式都会读取当前可见原生表单内同一行、卡片或分区已经填写的内容，
包括输入值、下拉框已选选项的显示文本、单选已选文本，以及只读/禁用控件的已有值。
这些内容仅作为相邻空白字段的 `existingContext`，不修改或保存回画像。

例如“关系＝母亲”已选择时，姓名、电话补母亲；同页父亲卡片分别使用父亲；
实习单位已填写且唯一对应第二段实习记录时，补该段记录的职位和时间。
明确家庭关系、家庭姓名、实习单位或项目名称线索会进一步限定每字段允许的真实来源。
缺资料、同类记录重复或线索冲突时跳过，不猜第一条。其他上下文由模型理解。

模式1遇到相邻已填线索时，将该空白字段交给模型优先判断；无上下文的字段仍先规则。
读取只取点击前的值，不把本次规则刚写入的内容当依据。默认保护已有信息不变。
每字段最多附带 8 条线索，每条值最多 240 字；密码、验证码、隐藏字段、密钥和条款不作为上下文。
使用模型时，这些已有页面内容也会发送到 DeepSeek；任务进度只保存统计，不保存这些上下文值。
等待期间已引用的关系/姓名等线索发生变化或被删除时，不应用旧推断，需要重新点击。

## 主页新增用户信息

点击 **新增信息**，直接填写由自己定义的 **信息名称 + 真实内容**，不预设姓名、电话、学校等字段。
可添加、修改、删除多条资料；名称最多 120 字，内容最多 10000 字，最多保存 30 条。
保存只更新 `profile.extraInfo`，保留已有的基本资料和经历。完整编辑器再次保存/导出也会保留。
规则按名称精确匹配，模型结合名称含义、网页标签及同区域已有内容引用 `extraInfo.0.value` 等真实来源。
名称只用于理解，不作为填写内容。自定义家庭资料也可依据网页已选关系推断，例如已选“母亲”，
可匹配自定义的“母亲电话”；不要求把该资料另存入固定的家庭成员结构。

主页与悬浮面板已移除手动填写提示和家庭对象选择。程序每次读取当前页面已有内容推断，
模式1遇到相邻已填线索时优先使用模型，其余字段先规则；模式2全部用模型判断。

## 保护已有信息

两个模式默认开启 **保护已有信息（仅填空白项）**：

- 有内容的文本、日期、数字 0、部分填写的内容、有效下拉选择、已选单选组，以及“无”都保留。
- “请选择”等占位项才算未选择，包括 value 为 0 的占位项。
- 浏览器尚在编辑、值暂未提交的无效数字/日期输入也会跳过。
- 扫描时排除已有字段作为填写目标；相关已有值可作为上下文发送给模型。实际写入前再次检查，保护等待期间的手动补充。
- 在已识别的国家/省份/城市级联中，若子项已有内容，跳过父项并提示手动处理，避免触发清空。

用户补充完缺失信息后再次点击，只处理剩余空白项。
如确实需要更新已有值，可在主页明确关闭保护；重新打开主页会恢复默认保护。
悬浮入口始终启用保护，不提供覆盖开关。
网站自定义、异步或未知的联动仍需专门适配，不能保证拦截所有网站自身的副作用。

## 悬浮球与固定主页

HTTP/HTTPS 网页默认在视口右下角显示悬浮球。点击后展开两个填写按钮与本页结果；
滚动网页、点击表单不会关闭面板，点击球或关闭按钮可收起。
主页的 **网页右下角显示悬浮球** 开关可隐藏或恢复所有已打开网页的入口。

点击悬浮面板的 **新增信息 / 打开固定主页**，或主页右上角的 **固定窗口**，
会打开独立扩展窗口，点击网页其他位置不会让它像工具栏弹窗一样消失。
该窗口绑定来源网申标签页，填写操作该页面；完整编辑器独立维护本地资料。

悬浮入口用闭合 Shadow DOM 隔离样式，不嵌入可被任意网页加载的主页/密钥设置 iframe。
入口不读取画像值或 API Key，只通过受限消息获取准备状态、本页任务统计、启动本页填写或打开主页。
实现依据：[Chrome Content scripts](https://developer.chrome.com/docs/extensions/develop/concepts/content-scripts)。
这是网页内的固定悬浮入口，不是操作系统桌面的全局置顶窗口；浏览器内部页面等受限页面不显示。

## 规则与模型的分工

优先使用明确的关联标签、无障碍标签和技术属性进行规则匹配。
同一来源命中多个规则时，只有明确、更具体的嵌套匹配才直接采用；
歧义字段保留原值，并返回描述。排序分数不是统计置信度。

| 环节 | 规则/代码 | 模型的用途 |
| --- | --- | --- |
| 姓名、电话、邮箱等明确字段 | 本地直接匹配 | 通常无需调用 |
| 陌生表述或多个含义 | 返回字段描述与候选 | 结合标签、分区和画像内容映射 |
| 日期格式、长度、数值约束 | 本地转换和验证 | 不补造缺失的日或其他事实 |
| 下拉、单选、文本写入 | 根据真实控件类型执行 | 不生成或执行网页脚本 |
| 自定义组件、重复经历表单 | 需要专门的组件适配 | 理解字段不能替代控件适配 |

直接让模型处理整页会增加调用量、等待时间和需传输的数据；结构化输出也不保证
语义映射正确。规则覆盖明确字段，模型批量处理未识别或歧义字段，更适合当前项目。
效果需要用实际招聘表单测量，不能以模型自报的置信度直接决定是否填写。

## 填写引擎

- 标签与属性独立匹配，明确标签优先；标签不混入控件值和下拉选项。
- 保留冲突候选，不按规则顺序或画像是否有值猜测。
- 识别含义与操作控件分离，例如性别可以填下拉框，学历也可以填文本框。
- 对原生 date/month/time/datetime-local/week 控件转换并验证格式；
  只有年月的数据不能填需要年月日的日期框，不自动补成 1 日。
- 下拉框采用唯一的精确/别名匹配，排除禁用和空占位选项。
  不再通过包含关系把“接受”与“不接受”等混为一谈。
- 单选组限制在相同 form/name 内，整组只计数一次。
- 检查浏览器约束和写入结果；失败前尚未触发事件时恢复原值。
- 验证码、上传和同意条款保持手动处理，与弹窗使用说明一致。
- 区分缺数据、格式/选项不匹配、控件不支持、未识别和歧义。

模型收到的 `modelFields` 示例：

```json
{
  "fieldId": "field-12",
  "label": "最高教育程度",
  "section": "教育背景",
  "controlType": "select",
  "options": [
    {"optionId": "option-0", "text": "大学本科", "value": "bachelor"},
    {"optionId": "option-1", "text": "硕士研究生", "value": "master"}
  ],
  "reason": "unmatched",
  "candidates": []
}
```

待填写字段本身的标签不混入输入值。模型字段另含 `existingContext`，提供同一区域点击前已填写的内容；
模型请求还包含画像内容与全局/每字段允许引用的来源路径。
一次填写最多处理 300 个模型字段，每批最多 20 项。

## DeepSeek 判断与本地执行

请求固定发送至 `https://api.deepseek.com/chat/completions`，使用官方 JSON 模式，
明确要求返回 JSON，关闭思考模式。默认模型为 `deepseek-flash`，也可选择
`deepseek-v4-pro`。实现依据：[首次 API 调用](https://api-docs.deepseek.com/)、
[JSON Output](https://api-docs.deepseek.com/guides/json_mode/)。

模型返回的方案示例：

```json
{
  "assignments": [
    {"fieldId":"field-12", "sourcePath":"degree", "optionId":"option-0", "transform":"original"},
    {"fieldId":"field-13", "sourcePath":"family.0.name", "optionId":null, "transform":"original"},
    {"fieldId":"field-14", "sourcePath":"experiences.0.time", "optionId":null, "transform":"startDate"}
  ]
}
```

本地校验要求来源路径真实存在、字段 ID 属于本批、选项 ID 属于该字段。
不确定的字段用 `sourcePath: null` 跳过；未知或重复字段、不存在的来源/选项、
截断回答、空回答、非法 JSON 都不会执行。
模型自行生成的 `value`、`script`、`selector` 等额外属性会被丢弃。

插件从本地画像取出来源值，支持顶层字段、嵌套经历/家庭成员字段、整段经历数组。
可对真实日期来源做年份或起止日期提取，其他内容保持画像原值，不生成新的事实。
“空缺项填无”开关同时用于两种模式，仅适用于经历、语言、证书等允许填无的字段。

页面端保存节点引用、标签/分区/控件约束/选项指纹和原有值；
应用模型结果前逐项核验。DOM 重排不会依赖过期的数组索引；
节点被替换、选项变化、用户手动输入、页面导航时，旧结果会跳过或停止。

## 后台任务与数据处理

请求在 `background.js` 中运行，进度保存在 `chrome.storage.session`。
关闭弹窗后任务仍由后台处理，重新打开会读取进度和结果。
后台意外重启会报告中断，保留已填写内容，不自动重复计费请求。

每批首响应等待最多 25 秒，响应正文读取最多 60 秒；超时、网络错误、鉴权失败、
余额不足、限流都会显示错误。采用首响应单独超时是为了符合 Chrome 后台 fetch 的
生命周期限制，见 [Chrome 官方说明](https://developer.chrome.com/docs/extensions/develop/concepts/service-workers/lifecycle)。

Key 只放在 API 认证头，不放进模型提示词、任务进度或错误正文。
扩展限制 local storage 只供可信扩展上下文访问。后台拒绝网页消息；
本扩展顶层悬浮脚本只能使用上述受限消息，不能读取密钥或修改画像。
本项目采用用户自行提供 Key 的独立扩展方式，没有把共享服务密钥打包进插件。
使用模型时，字段描述、选项文本、同区域已有内容与所需画像内容会发送给 DeepSeek；弹窗已明确说明。

建议用实际招聘表单比较两种模式的正确填写率、误填率、耗时和调用成本。
纯模型模式仍可能选错来源或选项；结构正确不代表语义一定正确。

## 项目文件

- `manifest.json`：扩展入口和权限。
- `popup.html/css/js`：画像状态、自定义资料维护、填写与结果显示。
- `editor.html/css/js`：画像编辑与 JSON 导入导出。
- `fill-engine.js`：自包含识别与填写函数，可独立注入页面。
- `deepseek-client.js`：提示词、画像来源整理、API 请求与返回方案校验。
- `fill-controller.js`：两条路径的编排、分批填写与部分结果统计。
- `background.js`：后台任务、配置消息、文档定位与进度持久化。
- `floating.js`：网页右下角悬浮入口和固定面板。
- `profile.example.json`：示例画像。
- `icons/`：图标。
- `tests/`：原生控件回归、API 模拟、路径编排、弹窗与后台流程测试。

## 开发与测试

git clone https://github.com/BistuDu/Job-Application-Assistant.git

```sh
npm install

```

使用 Edge 时可设置 `TEST_BROWSER_CHANNEL=msedge npm test`。
浏览器测试使用独立临时 Chrome，只加载本地测试内容，不访问招聘网站或读取用户浏览器资料。
API 返回和 chrome 扩展 API 使用模拟适配器，实际执行弹窗、后台、客户端与 DOM 引擎源码。
测试不调用真实 DeepSeek，也不需要真实 Key；不验证账户余额或真实模型判断质量。

## 当前边界

每次点击扫描一次当前可见 DOM；不持续监听后来出现的字段。
不遍历 iframe/Shadow DOM，不操作完全由 div/span 实现的组件。
重复经历数组仍主要格式化成文本，不自动新增网站的经历行。
默认保留已有信息；只有在主页主动关闭保护时才允许直接覆盖。
未识别的网站联动可能影响其他字段，正式提交前仍需核对。
测试验证原生控件行为，不代表所有第三方网站或框架组件均已适配。
